# 决策、世界定义与持久化的边界规则

本文件记录 2026-11-16 对 `internal/agent`、`internal/pack`、`internal/store` 的测试重建。这三个包原有的 14 个测试文件已全部删除。新的测试按下列规则重新构造输入和判据，没有把旧文件改名后保留。

原测试完整备份已持久保存于本机 `.artifacts/original-tests-20261116.tar`。备份用于审计，不进入编译，不是备用测试入口。

## 怎样判断正确

每条规则都先说明独立依据，再说明反例和边界。测试中的期望值来自协议、明确的权限、测试自己声明的成本和合同，或数据库事务语义。测试不调用待测的报价、产量或守恒函数来计算同一函数的期望结果。

“没有报错”“总资产守恒”“世界运行了若干天”都不足以证明合同被正确履行。交易和收获测试还检查谁交出什么、谁实际收到什么、谁仍保有产权，以及没有同意的人是否被扣款。

离线规则选择器挑哪个配方、走哪条生活路线，不再充当模拟正确性的定义。历史村庄的初始粮食量、固定收获次数、收入或产量下限也不再充当独立依据。它们需要另行确定场景目标与校准来源。

| B9 | 快照和同一批事件必须共同提交或共同撤销；同一世界只能由一个持锁会话写入。依据是 PostgreSQL 原子事务和会话级排他咨询锁。 | 后一 SQL 批插入失败，前一批事件或新快照仍留下；连接池换连接使锁丢失；释放后锁仍留着；一个世界锁住另一个独立世界。 | 201 个事件跨过当前 200 行 SQL 分批，在第二批制造唯一键冲突，检查完整旧快照及唯一旧事件仍在；修正重复身份后全部提交。独立世界可同时持锁，原世界释放后可重获。见 `postgres_boundary_integration_test.go`。201 是触发跨批路径的测试规模，不是接口上限。 |
| B10 | 重放只消费已记录动作，不得新问模型。检查点 tick 的第一次决定也必须保存和加载。失败查询不等于空历史。依据是可重复执行与可见错误要求。 | 非零检查点漏首 tick；缺日志时自己补动作；重放再发模型请求；查询失败显示“无事件”；跨世界读取他人的检查点、日志或事件。 | 本地两个接口产生真实 HTTP 请求并记录动作后关闭服务，再重放得到相同状态和事件且请求数不增。另修改返回动作、返回日志、传入重放日志、重放返回动作的嵌套 `Care`/`Statement`，已存条款均保持不变。数据库用 tick 37 检查首条日志、最近但不晚于目标的检查点、事件范围与排序、独立 world ID。见 `replay_boundary_test.go` 和数据库测试。 |
| B11 | 压缩事件只删明确的日常噪声，保留因果、经济、失败和未知新事件的身份、次序和正文。依据是审计不能因节省空间丢掉重要证据。 | 只保留统计数而改写事件；删除只有来源的发言、数量为 0 的声明或失败；未知事件默认删除。 | 检查完整保留对象和顺序，空输入不生成历史。见 `event_boundary_test.go`。压缩后的事件不替代完整决策日志，也不能单独承担精确重放。 |

协议和数据库依据已通过 Context7 核对：

- [TypeSafe Choice 定义](https://github.com/typesafe-docs/typesafeai/blob/main/docs/04-primitives/choice.md)；[System One 请求协议](https://github.com/typesafe-docs/typesafeai/blob/main/docs/09-api-reference.md)。最多 255 个选项来自该协议。
- [RFC 8259 第 2 节](https://www.rfc-editor.org/rfc/rfc8259#section-2)：一个 JSON text 是单个序列化值。B2/B8 要求接口只接收一个定义对象；不是悄悄只处理前缀。
- [PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html)：共同成功或共同撤销。
- [PostgreSQL 咨询锁](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)：会话锁保持到同会话显式释放或会话结束；[锁函数](https://www.postgresql.org/docs/current/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)。

## 执行入口与证据边界

默认测试：

```sh
go test ./internal/agent ./internal/pack ./internal/store
```

默认入口只使用本机内存和本地 HTTP 测试服务。它不根据 `.env`、模型密钥或数据库地址隐式连接外部服务。

真实数据库入口：

```sh
WRE_TEST_DATABASE_URL="$DATABASE_URL" go test -tags integration ./internal/store -v
```

连接变量由执行者显式注入。测试不读取 `.env`，不输出连接字符串。缺少 `WRE_TEST_DATABASE_URL` 时明确失败。测试只为新生成的 `test-boundary-<128位随机值>` 世界写数据；清理语句都带该 world ID，不选择、修改或删除既有世界。这个前缀不授予删除其他同名前缀世界的权限。

本地服务测试的名称均带 `Local` 或 `Protocol`，正文明确写出用途。它们验证请求、响应、拒绝错误和模型调用边界，不是“真实模型 e2e”。真实模型完整流程与 trace 审查由主线程执行并另存证据。重放本地调用计数为零的证明，不等于真实模型决策质量合格。

2026-11-16 最终实际结果：

- `go test -json -count=1 ./...`：全仓通过。agent 30、pack 5、store 1 个顶层测试通过。此前贷款现金不足仍展示接受候选的问题已在源头修复，恰好足额和仍可拒绝的对照均保留。
- `go test -race -tags integration -json -count=1 ./...`：全仓通过，含真实 PostgreSQL。四个数据库逻辑测试与事件压缩测试全部通过；agent 的并发预算分配和本地 HTTP 并发访问也通过。
- 更早已实际执行 `go test -tags integration ./internal/store -count=1 -v`：五项通过，耗时 0.228s。

## 新增检查、限制、兜底、重试

本子任务没有修改运行时 Go 文件。运行时新增检查、限制、兜底、重试：**无**。

测试入口新增一项明确要求：显式选择 `integration` 后必须提供 `WRE_TEST_DATABASE_URL`。依据是任务要求外部测试真实运行，不能用 Skip 冒充完成。它只挡住“要求运行数据库测试但没有提供目标连接”的执行方式，不限制正常产品请求。随机 world ID 和按身份清理用于隔离测试数据，不限制产品世界身份。

测试发现的运行时问题由主线程在源头修复。其新增校验及行为变化应由主线程的交付记录逐项说明。新增测试没有设置重试、吞错、离线兜底、收入下限或产量下限。
